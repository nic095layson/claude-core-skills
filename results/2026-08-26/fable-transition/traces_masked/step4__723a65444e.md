**Not ready to ship.** It works for clean ASCII data with no punctuation, but it isn't actually producing CSV — it's producing comma-joined strings, and the run above shows the file silently corrupts on ordinary inputs.

## Confirmed bugs (reproduced above)

1. **No CSV quoting/escaping.** `"Smith, John"` becomes two columns; a name containing a newline splits into two rows. A downstream reader gets 6 rows instead of 5 with shifted columns — no error, just wrong data. Any real user table will hit this ("Last, First" names are common).
2. **`None` is written as the literal string `None`.** A missing name should be an empty cell, not the text `None`.

## Plausible problems (not reproduced, but real)

3. **No `encoding=`.** `open(path, 'w')` uses the locale default. On Windows or a `C`-locale container, a name like `José` raises `UnicodeEncodeError` mid-export — which also leaves a **half-written file at `path`** because there's no temp-file/atomic write.
4. **No `newline=''`.** Required by the `csv` module on Windows to avoid `\r\r\n` line endings.
5. **A `KeyError` on a missing key also leaves a partial file behind.** Whether that's acceptable depends on who consumes the output.

## Fix

```python
import csv

def export_users_to_csv(users, path):
    with open(path, 'w', newline='', encoding='utf-8') as f:
        w = csv.DictWriter(f, fieldnames=['id', 'name', 'email'], extrasaction='ignore')
        w.writeheader()
        for u in users:
            w.writerow({k: ('' if u.get(k) is None else u[k]) for k in w.fieldnames})
    return path
```

`csv.DictWriter` handles quoting for commas, quotes, and embedded newlines; `utf-8` + `newline=''` make it portable; the `None → ''` mapping fixes #2. If a partial file on failure matters to you, write to `path + '.tmp'` and `os.replace()` it at the end — I left that out since it's a judgment call about your consumers.

One non-code note: this exports email addresses, so make sure the output path isn't somewhere world-readable or checked in.
