## A. Where a turn begins

| # | Question | Spec says | My choice |
|---|---|---|---|
| A1 | Turn start | "the owner's latest message or, when later, the latest scheduled run (-1: none)" (turngate.py:107) | max(owner index, scheduled index). |
| A2 | No owner message and no scheduled run (-1) | Silent on what the gates do. "an unreadable transcript yields 'no turn'" covers only unreadable files. | F1: the whole transcript is the turn (the rule still applies to what was done). F2: there is no owner word, so a merge is denied (deny:merge-word). |
| A3 | What is an owner message | "Only un-marked user text counts" (isMeta / isCompactSummary skipped); "Harness-generated user turns (background-task notifications, wake envelopes, subagent hand-backs) are not the owner's request either"; content may be a string or a list of blocks. | type=user, not isMeta, not isCompactSummary, not isSidechain, content is a non-blank string or a list with text blocks and NO tool_result block, and the text does not START with a harness marker. |
| A4 | Which markers, and where in the text | Silent: no list is given. The catalog shows `<task-notification>`, `<command-name>`, `<local-command-stdout>` as observed leads. | Marker must be at the START of the text (after whitespace): `<task-notification`, `<command-name>`, `<command-message>`, `<command-args>`, `<local-command-stdout>`, `<local-command-stderr>`, `<local-command-caveat>`, `<system-reminder>`, `<wake`, `<webhook-payload`, `<child-session-event`, `<agent-message`, `<bash-input>`, `<bash-stdout>`, `<bash-stderr>`, `<user-prompt-submit-hook>`, `[SYSTEM NOTIFICATION`, `[Request interrupted by user`, `Stop hook feedback:`, `Caveat: The messages below were generated by the user while running local commands`. A message that merely MENTIONS a marker later in its text is still the owner's. |
| A5 | Owner input that is not a user row | Silent. The catalog says attachment rows of type queued_command "carry owner input" (origin.kind 'human'; 0 seen in the real record, 1 task-notification). | An attachment row with attachment.type == "queued_command" and origin.kind == "human" IS an owner message (text = attachment.prompt). Other queued_command origins, queue-operation rows and last-prompt rows are not. |
| A6 | Scheduled run row | "arrives as a ReadNotifications tool_result whose text has one header line per notification; only the header form counts" (turngate.py:80-84); regex in the kit report: `^--- Notification .*· origin: scheduled trigger` (multiline). | A user row holding a tool_result whose text matches that regex AND whose tool_use_id belongs to a tool call named ReadNotifications. A result that answers some OTHER tool (Bash, Read) never starts a scheduled run, whatever it prints. Result content may be a string or a list of text blocks. |
| A7 | A header-looking line inside a notification BODY (bodies are "external content relayed verbatim") | Silent. | Counts (the stated regex cannot tell it from a real header). Recorded as a weakness of the stated rule, not of either implementation. |
| A8 | Rows that never start a turn | task notifications, GitHub notifications, isMeta rows, compaction summaries, tool results, attachments other than A5, system rows | as stated. |

## C. F2 (merge-word gate) and the scheduled-run rule

| # | Question | Spec says | My choice |
|---|---|---|---|
| C1 | What is "a PR merge" | "`*merge_pull_request`, `gh pr merge`" | Tool leaf name merge_pull_request; a parsed `gh pr merge` invocation in a Bash command (same shell parsing as B7; flags may sit between the words, e.g. `gh pr -R o/r merge 34`; `--help` is not a merge). Decisions beyond the two named forms: leaf enable_pr_auto_merge (B3) and the API route (B9). NOT a PR merge: `git merge ...` (the fixture note says branch sync is allowed), update_pull_request_branch, any Edit/Write whose text mentions the words, a Bash command that only mentions the words in quotes, a comment or a file body. |
| C2 | "merge" (word) | "(word)" | Case-insensitive, exactly `merge`, not preceded or followed by a letter, digit or underscore. "merged", "merging", "mergeable", "emerge", "merge_pull_request" do not count; "merge-and-report", "pre-merge", "Merge." do. |
| C3 | Negation | "an occurrence counts only when no negation sits in the few words before it" (turngate.py:185-186). Silent on the list and on "few". | Negations: no, not, never, without, cannot, nor, neither, and any word ending in n't (straight or curly apostrophe) or one of dont/wont/cant/shouldnt/wouldnt/didnt/doesnt/isnt/mustnt. "Few" = the 3 words before the occurrence. No sentence-boundary logic (the rule states none). One un-negated occurrence is enough. The same test is applied to all three sources (message, click, assistant text). |
| C4 | Negation AFTER the word ("merge? no", "Merge — not yet") | Not covered by the stated rule. | Counts as the owner's word (literal rule). Recorded as a weakness of the stated rule. |
| C5 | "the owner's latest message" | as stated | The latest owner message per A3-A5, only that one (an older "merge" does not carry over). |
| C6 | "a clickable answer after it" | "The chosen options of an AskUserQuestion answer ("question"="choice"), never the question text" | A tool_result after the owner's latest message whose tool_use_id belongs to an AskUserQuestion call (orphan id: only if the text starts with "Your questions have been answered:"). A result answering another tool (Bash, Read) is never a click. Choices = the right-hand side of each "q"="a" pair. A question "Merge?" answered "Yes" is NOT the word (the rule says never the question text). A later click does not cancel an earlier one (the rule states no such thing). |
| C7 | "the assistant's last text before that message together with the PR's number" | as stated | The last assistant row before the owner's latest message that carries non-blank text; it must hold an un-negated "merge" word AND the PR number as a whole number (not part of a longer number). Needs a known number: tool input pullNumber / pull_number / number / pr_number / prNumber, or the first positional of `gh pr merge` (digits or a .../pull/N URL), or the API path. No number known => this clause cannot allow. Thinking blocks are not text. |
| C8 | Does the owner's reply matter for C7 (assistant: "Shall I merge #34?", owner: "No") | The stated rule does not look at the reply. | Literal: allow. Recorded as a contradiction between the detailed rule and its headline "a PR merge is denied without the owner's word" (README:15). |
| C9 | How far back may "the assistant's last text" be | Silent. | Any distance (literal), even across earlier owner messages. |
| C10 | Scheduled run | "A scheduled run carries no owner message, so it carries no owner word to merge: it never merges" | If the turn starts at a scheduled-run row (A6), every PR merge is denied (reason contains "scheduled run never merges"), clicks and assistant texts notwithstanding. An owner message after the notification makes it an owner turn again. |
| C11 | Errors | "Fails open on every error" | Missing/unreadable transcript or bad payload => allow (even for a merge). |
| C12 | The pending tool call may or may not already be a row of the transcript | Silent. | Irrelevant to my F2 (it reads only owner message, clicks after it, assistant text before it). |
| C13 | F3 advisory | out of scope | not implemented; my hook prints nothing unless it denies. |
